# Windows 26.1106 兼容性范围

`OpenAI.Codex 26.1106.6628.0` 的前端改用 webpack 懒加载模块，同一服务档位权限函数会出现在多个 `webview/assets/async/` 资源中。旧版启动器只检查顶层资源，且每个权限函数要求归档中唯一，因此会报告缺少签名并停止。

新增适配保留旧版 `26.1023` 的唯一签名规则。webpack 适配仅对已核验的整份 `app.asar` SHA-256 `54b74a9131680fc9eead711ed5d9f718f6127c22222ca60d2e3b577a707e2485` 启用，并要求准确匹配 7 份菜单权限函数及 8 份请求权限函数。其他整包指纹不能借用这个重复匹配规则；客户端更新后需要重新核验。

15 份资源只在本次启动的内存响应中替换。每份原文和补丁后内容都有独立 SHA-256；启动前后继续核对整包指纹，补丁后模块必须通过 JavaScript 语法检查。运行时仅处理计划中列出的原生 `app://` 资源路径，不修改安装目录。

API Key 和空认证的自定义供应商可使用原生 Fast，Ultrafast 继续关闭。ChatGPT、PAT 和 Bedrock 保留服务端返回的权限；Copilot 和未知认证类型继续使用原有拒绝规则。菜单 hook 的缓存依赖使用实际认证方法，避免在不同非托管认证之间切换时保留旧权限。

本轮语义、歧义、缺失／多余副本、未知整包指纹、变更中止和模块语法测试均通过；已安装程序的只读 `inspect` 也通过。它们确认适配计划完整，不能代替完整桌面菜单与出站档位的隔离验收。最终桌面验收结果记录在 [验收记录](validation.md)。
